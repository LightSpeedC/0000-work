見張り番が転んだら、そのまま通してしまう?

企業向けの手引き (11/23) に、いちばん「うちにも関係がある」話がありました。PreToolUse フックは、コマンドが走る前に止められる見張り番です。ところが、その見張り番が失敗したり時間切れになったりすると、既定ではそのまま通ります。

手引きは、失敗したときの動き (onFailure) を block にして、転んだら止める側に倒すよう勧めています。

案 1 ・ hook止めるためのフックは、失敗・時間切れでも止まる設定にする

何を足すか
実行を止める目的のフックを置くとき、失敗・時間切れのときも止める設定 (onFailure の block) にする、という決めごと。
なぜか
記事によると、フックが失敗・時間切れになると既定では通ってしまう。止めたいものほど、見張りが転んだときに素通りしては意味がない。
先に確かめること
いま入れている Claude Code (2.1.332) に onFailure があるか。まだ確かめていません。ai-agent-rules にも、PreToolUse や onFailure を扱う決めごとは今のところありません。

みんなで同じノートに書いたら、57 件のうち 16 件が消えた

「The components of agent memory」(11/06) には、複数のエージェントが同じファイルに同時に書く実験が載っています。57 件の事実を書かせたところ、残ったのは 41 件。1 エージェントにつき 1 ページへ分けると、57 件が全部残りました。

うちの Vault は、日誌に複数のセッションが書き込みます。同じ日の日誌を同時に書くことがあるなら、同じことが起きうる話です。

案 2 ・ rule同時に書かれうる共有ファイルは、1 セッション 1 ファイルにする

何を足すか
複数のセッションが同じ日に書く日誌 (Vault) などは、セッションごとにファイルを分け、あとで束ねる、という決めごと。
なぜか
同じファイルへの同時書き込みは、気づかないうちに内容を失う。実験では 57 件中 16 件が消えた。
先に確かめること
既にある safe-push で足りるか。足りるなら、新しい決めごとは増やさない。

200 行目から先は、なかったことになる

同じ記事に、Claude Code の自動メモリの話があります。MEMORY.md は、先頭の 200 行・25KB までしか起動時に読まれません。それより後ろは、書いてあっても文脈に入りません。

常時稼働エージェントの記事 (11/13) も、起動時に読み込む文脈は軽くしておくよう勧めています。同じ考え方を当てると、AGENTS.md から読み込む共通ルールやローカルルール、!memory.md のような、起動のたびに読むファイルが対象になります。

案 3 ・ rule起動時に読むファイルは、大きさの上限を決めて小さく保つ

何を足すか
起動のたびに読み込むファイル (!memory.md・ローカルルールなど) に、行数やサイズの目安を決める。上限を超えたら、詳しい話は別のファイルへ逃がし、先頭からはリンクで辿らせる。
なぜか
読まれない部分は、書いていないのと同じ。しかも毎回の起動で、読み込んだ分だけ文脈を使う。
先に確かめること
記事が言うのは MEMORY.md の読み込みの上限。AGENTS.md の側に同じ上限があるかは、確かめていません。

「python なら何でも OK」は、合鍵を配るのと同じ

手引きの記事は、許可の書き方にも踏み込んでいます。見る順番は deny → ask → allow。そして Bash(python:*) のような、広すぎる許可は避けるように、と。python では何でもできるので、「python は許可」は実質「何でも許可」だからです (この「合鍵」はたとえで、記事の言い回しではありません)。

ほかにも 2 点ありました。サブエージェントは親の許可をそのまま引き継ぎます。Bash のコマンドは分割され、分けた 1 つずつが検査されます。

うちの共通ルールには、add_repo の許可を書くとき「ツールは 1 つずつ書き、ワイルドカードは使わない」と、既に書いてあります。案 4 は、その考えを許可全般へ広げるものです。

案 4 ・ rule許可は狭く書く。実行環境ごと許す書き方はしない

何を足すか
Bash(python:*) のように、実行環境そのものを許す書き方をしない。許可は 1 つずつ、deny → ask → allow の順で考える、という決めごとを、add_repo の分だけでなく許可全般に置く。
なぜか
python や node を丸ごと許すと、その先で何でも走る。サブエージェントは親の許可を引き継ぐので、広い許可は広がる。
先に確かめること
今ある許可の置き場 (ホームの設定とプロジェクトの設定) に、広い許可が入っていないか。
